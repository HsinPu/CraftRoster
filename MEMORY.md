# Project Memory

Record verified, durable project decisions and lessons here. Current catalog and package files remain authoritative for versions and counts.

## Catalog and installation

- User-facing purpose bundles are separate from Skill source categories. The former are maintained in `scripts/data/install-bundles.json`; the latter in `scripts/data/skill-catalog.json`. One component may belong to multiple purpose bundles and is deduplicated by destination.
- Skill `required` dependencies expand recursively. `conditional` / `optional` dependencies and `related` / `alternative` routes must not be treated as blanket installation requirements. Agent support additionally distinguishes `recommended` edges.
- Check actual Skill instructions before inferring coverage from names: `desktop-development` currently owns Electron, and `swiftui-development` currently targets native iOS. Neither proves complete Windows/macOS native UI support.
- Seven `svg-` packages are independently installable. Their source notices, local resources, conditional handoffs and purpose membership were validated in the SVG implementation and optimization work; see `docs/svg-skills.md`.

## Verification lessons

- SVG structural preflight is not a renderer, sanitizer, full CSS parser, or visual approval. Namespace handling, effective `href` selection, bounded CSS scanning, and strict viewBox grammar protect against previously reproduced false results.
- Changes to the source manifest can invalidate explicit local digests in evaluation fixtures. Recheck `tests/skill-three-provenance-fixtures.test.js` and the referenced policy fixture when `scripts/data/skill-reference-sources.json` changes.
- Use a supported Node runtime before interpreting test failures; sandbox child-process errors such as `EPERM` can prevent a test from executing at all. Distinguish environment failures, actual failures, unexecuted cases and successful checks.
- Some package and installation tests create temporary files while running. Wait for their processes and cleanup to finish before staging; inspect the staged diff to exclude test sentinels and Python caches.
- Windows CI can expose TEMP through an 8.3 alias such as `RUNNER~1` while .NET resolves full directory names. Use `fs.realpathSync.native` consistently for fixture roots and cleanup boundaries rather than weakening path-equality assertions.
- Purpose and category changes can leave stale counts or names in README CLI tables, command comments and CLI tests outside generated blocks. Check those separately; derive total-count expectations from the canonical registry while explicitly checking new purpose visibility. Give linked HTML `details` sections explicit anchors rather than relying on their visible `summary` text.
- GitHub can return HTTP 301 for a moved public repository even when its pinned commit and tree remain intact. `supatest-ai/awesome-claude-code-sub-agents` moved to `tryalan-ai` with unchanged pinned evidence; the Agent verifier must follow bounded HTTPS redirects within `api.github.com`, including `/repositories/<id>/git/...`, and retain all provenance checks. `test:agent-references` covers redirects, failures and rejected provenance without network access.
- A referenced SPDX license can pass local manifest validation while its remote content matcher lacks that license branch. Impeccable's valid pinned Apache-2.0 LICENSE exposed this gap; keep its source/blob pins intact and test the actual `verifyRemote` path with positive license text, negative terms and mismatched license blobs.
- OpenCode v1.19.5 accepts comments/trailing commas in both `.json` and `.jsonc`. Its global load order is `config.json` then `opencode.json` then `opencode.jsonc`, with higher explicit instruction arrays overriding lower arrays. When adding an array to a file that has none, carry forward the effective lower array; otherwise only append to the target's own array. Keep legacy `config.json` discovery limited to the standard global directory, preserve source bytes and all candidate snapshots, and keep ownership parsing strict JSON.

## Blender implementation — 2026-11-04

- Version 1.5.0 retains 108 `blender-` packages and adds standalone `game-design` / `godot-development`; the `game-development` purpose installs 110 Skills with four Agents. The same-named Skill source category contains only the two design/engine packages. `docs/blender-skills.md` owns usage; the coverage ledger maps 126 canonical entries and 443 inventoried files from all four pinned repositories. No upstream tools or MCP hooks are installed by the packages.
- The foundation is standalone. Specialist packages require its shared references with `usage: resource`; export also requires asset-validation. Optional routing does not expand every production package or pull an unrelated game-engine category.
- Engine-specific exporters additionally require common export, giving a four-package closure. Style/world entries combine conditionally with disciplines; subtype descriptions alone are insufficient, so detailed variant resources carry operational recipes and failure handling.
- Geometry Nodes can retain unused empty material slots. Material requirements must inspect evaluated polygon assignments; an unused slot does not mean a missing surface material. The native regression distinguishes it from one actually unassigned face and a mesh with no materials.
- A batch process can exit zero without producing its promised artifact. Check per-job status, timeout, unique portable paths, nonempty expected files and source hashes; retain other job results when one worker fails. These checks do not sandbox trusted scripts or prove artifact semantics.
- A Geometry Nodes field connected to a single-value primitive input can collapse a part while overall scene bounds still look valid. Inspect per-part dimensions and degenerate triangles, and explicitly sample a single value when required. The 5.2.2 forward trial also exposed modifier-input RNA changes; query the installed build rather than applying legacy ID-property code blindly.
- Actual image review, technical measurements and engine acceptance are independent. Read-only visual reviewers return findings; authorized writers render, correct and archive reports. Source/contract/image/export hashes bind a delivery revision but cannot establish visual judgment or authenticate a reviewer.
- Blender 5.2.2 native fixtures exercise evaluated geometry, source preservation, rig/clip/deformation GLB roundtrip and measured reference-proportion correction. CI host-only tests explicitly skip native checks without `BLENDER_BIN`; synthetic calibration and reimport do not establish art quality or target-engine behavior.
- Check every evaluated world coordinate and transform for finite values before reducing bounds: NaN can be hidden by min/max. Reject empty or nonstring engine-check descriptions rather than accepting any nonempty list as executed evidence.
- arjun988's 94 canonical Skills have a Cursor mirror and shared sibling references; do not double-count the mirror or copy isolated folders without their resources. EL4CTEO's 28 Skills provide live/headless paths and script-based QA; their presence does not establish cross-platform or engine success.
- Reimport reports and visual similarity metrics are partial evidence. majidmanzarpour's roundtrip script does not automatically compare the delivery manifest, and silhouette normalization does not prove world scale. setcodes includes author-specific FBX preferences and a distinct Blender Lab MCP protocol; adapt both to explicit project/tool contracts.
- Registered mask comparison requires matching declared orthographic windows; independent bounding-box normalization can hide both translation and size error. The helper measures explicit binary masks, verifies input hashes and refuses output replacement; it cannot establish calibration truth, depth or visual quality. PNG decoding is optional through an existing Pillow interpreter; JSON/P2 PGM remain standard-library paths.
- GLB color replacement appends an image and texture so shared users and the original binary bytes remain intact. Validate actual resource fields while retaining `extras` as opaque metadata; recursively interpreting `extras.uri` or `extras.sourceTexture` as glTF schema incorrectly rejected valid assets. Native Blender reimport exercised selected-image change plus geometry/PBR preservation, not all rigs or formats.
- Importing a helper from a Python test can create `__pycache__` inside an installable package. Disable bytecode writing before test imports, retain the nested npm exclusion, and exercise the package gate's `.pyc` sentinel; a clean Git diff alone does not prove a clean npm or local installation payload.
- Godot synthetic events may dispatch after a single `process_frame` wait when input accumulation is active. Observe callback delivery before assertions. The isolated delivery prototype passed 27 runtime checks after repairing the harness timing; that is not physical-input, visual, game-feel or human-playtest evidence. See `docs/audits/four-source-integration-2026-11-04/`.

## Interface-quality implementation — 2026-10-29

- `frontend-design-review` already separates experience critique, production web audit and polish review. It is read-only unless fixes are separately authorized. `docs/visual-design-skill-sources.md` records prior Impeccable research; adding three duplicate web review Skills would miss the actual native-platform gap.
- Impeccable was inspected at `5e745ace7e151feb2a93d360d0281fe39448b857`. It has one Skill entry, command playbooks, an engine launcher, and explicit iOS/Android native references. Host binaries for Windows/macOS do not establish native Windows/macOS application design coverage.
- Version 1.2.0 adds independently installable `ui-improvement`, writer `ui-improvement-engineer`, and the `interface-quality` purpose. Native Windows/macOS/iOS/Android have separate framework rules; mobile web and native mobile remain distinct.
- Preserve original brands, platform conventions and established design systems. Apply critique/audit as diagnosis and polish as scoped implementation; do not turn a request to inspect into permission to redesign.
- Current usage and limits are in `docs/interface-quality.md`; the original planning requirements remain in `docs/interface-quality-skill-plan.md`. The full native runtime matrix is not complete merely because the rules and evaluation inputs exist.
- `frontend-design-review` and `visual-regression-testing` are now conditional on the shared visual reviewer and direct members of `web-interface`. Real plan regression preserves its prior 55 Skills/11 Agents as a subset. The common interface purpose defaults to 2 Skills/3 Agents without pulling in all frameworks.
- Installation membership is not a permission boundary. A shared Skill can contain diagnosis and implementation modes, but a read-only role cannot write product files or archive reports merely because a mode or bundle names polish.
- Native source fixtures are partial inputs. Explicit model samples produced source repairs; actual browser evidence covers web/renderer HTML only. Source assertions and an accessibility tree do not establish a native build, screen-reader journey or target-runtime pass. Results are recorded separately in `docs/audits/interface-quality-2026-10-29/`.
- UIKit `keyboardLayoutGuide` does not follow undocked keyboards by default. An affected iPad repair must deliberately address `followsUndockedKeyboard` and tracking constraints; a phone-only fixture does not prove floating-keyboard behavior.
- No upstream engines, hooks, browser extensions or native SDKs were imported for this feature. The repository's Node validators passed; the separate skill-creator Python quick validator was unavailable because its PyYAML dependency was absent.
