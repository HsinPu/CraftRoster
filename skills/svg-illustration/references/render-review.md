# Review an illustration at its delivery size

Fix a useful comparison configuration: SVG candidate, renderer/version, viewport, pixel density, fonts, background, and capture scale. Browser and static renderers may differ, especially for text, filters, masks, and CSS. Compare candidates using the same configuration before attributing differences to artwork.

Inspect the final preview in this order:

| Concern | Observable defect | Useful correction |
| --- | --- | --- |
| Recognizability | Subject cannot be identified at delivery size | Improve the silhouette or key feature |
| Completeness | A requested part is absent | Add the missing semantic part |
| Attachment | Handle, wing, or stem floats | Adjust its joint or deliberate overlap |
| Occlusion | Foreground incorrectly hides a face or detail | Repair paint order, clipping, or grouping |
| Composition | Focus is crowded or cropped | Move whole objects before editing their contours |
| Legibility | Small gaps close and strokes disappear | Adjust the local geometry for the target scale |
| Surface | A transparent edge disappears on one background | Review light and dark surroundings |

Keep intended irregularity when it contributes to the design. Check the actual local change rather than treating all asymmetry as an error. A large image can conceal weak small-size recognition, and a small image can conceal broken paths.

For each material correction, note the affected ID, visible problem, and intended outcome. Capture the revised candidate and compare it with the retained best result. Do not accept a revision merely because it contains more detail or has a newer timestamp.

Optional pixel metrics can reveal an unintended change under controlled rendering. They cannot decide whether a character has the right expression, an illustration meets its brief, or an accepted design should be replaced. Report what was actually viewed, including the final result after any serialization, simplification, or export.
