# Narrative presentation branches

## Visual novel background plates

Collect final aspect/resolution, dialogue/name/choice masks and standing/seated/close-up character occupancy. Build depth layers—foreground frame, actor plane, story prop and background—without modeling interface text into the scene. Lock reusable camera and furniture transforms before making morning/evening or clue-state variants. Separate intentional narrative changes from lighting changes in a state table.

Render clean plate and actor-overlay review, including the largest character/crop. Use depth of field only after a sharp diagnostic confirms story-object readability; not every VN needs painterly treatment or blur. If a shelf crosses a character's face, repair owned staging/crop within the approved contract. If day/night variants move a clue, restore common layout. Deliver clean/graded plates, camera/state manifest and requested depth/alpha layers with actual output dimensions. Asset approval is not proof of dialogue pacing or UI integration.

## Interactive movie and branching shot set

Use a shot/branch continuity sheet: camera ID, lens/sensor, actor marks, eyelines, prop states and transition frames. Build the set and actor stand-ins once, then add shot/reverse-shot cameras preserving the chosen axis or explicitly planned axis crossing. Critical props must be reachable and consistently handed between shots. Branch-specific changes belong to named collections/actions, not an undocumented global scene edit.

Light faces and action through motivated sources while preserving continuity of key direction and practical status. Review a contact sheet in edit order plus branch alternates; reflections can expose missing actors or camera rigs. If a reverse angle changes object side/height, correct state or staging instead of hiding it with a tight crop. Deliver camera/prop-state map and timed preview if authorized. A branching shot library does not establish editing logic, performance or audience comprehension.

## Walking simulator and eye-height storytelling

Build an arrival, object-inspection point and return view using the supplied eye-height/FOV/controller envelope. Place environmental clues at meaningful viewing/reach distances and support a subtle hierarchy without making every story object glow. Model reverse sides and interiors visible during movement; a plate-only facade cannot serve a walkable set.

Use actual practical/window light and a brighter diagnostic. Inspect low/high eye positions if supplied, close object view and return-route landmark. If the clue is visible only from the hero screenshot, repair placement/occlusion while retaining story scope. If important narrative surfaces are hidden by blur, fix focus or camera distance. Deliver camera/proxy samples, clue states and full set dependencies; sampled rays/views do not prove controller collision, interaction or navigation.

## General story-driven scene continuity

For a scene not fitting the above, decompose the beat into beginning, changed object/actor state and resulting view. Build only the required state differences and retain a common source. Use material/light hierarchy to make the change readable, then compare with effects disabled. A narrative prop that changes appearance must keep its identity and attachment unless transformation is intended.

Deliver a beat/state/shot table and matched images showing the actual change. If the difference is invisible at delivery size, revise shape/placement/value before adding explanatory text. Label emotional and interpretive goals as judgments, not measured audience outcomes.
