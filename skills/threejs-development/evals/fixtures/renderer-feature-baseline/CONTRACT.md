# Existing renderer feature baseline

This is a fictional existing WebGL shader panel, with fixed Three.js 0.180.0 and no framework, external assets or third-party post-processing package. The visible color panel is drawn by real shaders through two render targets, then displayed on the canvas. It is deliberately small enough to isolate the renderer contract. This is input source for a renderer migration decision, not an already implemented WebGPU/TSL migration or a performance benchmark.

Preserve the contract in `contracts/requirements.json`: linear RGBA8 intermediate data, an optional invert post pass, asynchronous application-facing readback, bounded pixel dimensions, semantic controls and a recoverable lost-context state. The existing backend implements readback synchronously behind that Promise interface. A new implementation may schedule it differently, but must preserve pixel values and error behavior. Output encoding happens on the final display pass. Do not compare an sRGB screenshot directly with linear render-target bytes.

The target list names desktop WebGL2, mobile Safari, a proposed WebGPU path and an optional XR preview. It is a support/verification request, not evidence that these environments are available or passed. No headset, Safari, production GPU fleet or trusted existing benchmark result is supplied. The XR capability probe asks whether a session type is supported; it does not enter a session, render XR, or prove feature parity. A missing environment must remain explicit. No external deployment is requested.

Copy the family into a fresh temporary directory, run `npm ci --ignore-scripts --no-audit --no-fund`, `node tools/build.cjs` and `node tools/serve.cjs 4181`. Open the printed loopback URL. The static build contains the pinned installed Three.js modules and their license. Do not install dependencies or create `dist/` in the canonical fixture. Readback, invert, context loss/restore and a 60-frame CPU submission sample have separate controls; only claim observations actually executed. Restore/close the page and stop the server after testing.

Diagnostics report actual `renderer.info` object counts, draw calls and CPU wall time. They are not allocated GPU bytes, GPU timings or physical-device certification. No model outcome, private grader, migration implementation, completed feature matrix or chosen backend decision is included in the public files.
