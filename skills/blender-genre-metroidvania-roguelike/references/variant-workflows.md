# Persistent exploration and run-kit branches

## Metroidvania persistent world and ability gates

Use supplied jump/climb/ability envelope, camera plane and access rules. Build an entrance room, vertical connector and remembered landmark with compatible floor/door sockets. Stage a future destination visible beyond an ability gate and a return approach that reveals the same landmark from a changed direction. Give gates locked, unlocked/open and inactive states with stable opening bounds; an inactive visual effect must not accidentally imply traversability.

Reserve distinctive construction for secret surfaces and ability interfaces, rather than using the same crack/glow on every damaged wall. Use region materials that survive backtracking and camera changes; fog cannot hide missing depth or connection seams. If revisited rooms are unrecognizable, alter major landmark/profile, not only hue. If a decorative lip appears to grant an unapproved ability, repair art/proxy agreement. Deliver socket/vertical section, return-view contact sheet and gate/secret state table. Progression reachability and controller acceptance require the game.

## Roguelike recombinable rooms

Define socket position, outward normal, floor elevation, opening clearance, legal rotations, entry keep-out region and compatible neighbors. Build representative ordinary, connector and elite/special rooms with the same socket contract. Assemble at least two deliberately different combinations, including a rotated room and height/corner junction where allowed. Test each arrival camera before dressing; room internals must not cover the door-opening envelope.

Keep room/function identity through stable silhouette and non-color markers, with variation inside approved bounds. If a rotated room opens into a wall, correct compatibility/orientation metadata and geometry; do not claim the generator will avoid it. If every irregular wall looks secret, separate secret construction grammar. Deliver module/rotation/socket inventory and arrangement renders with measured seam/floor differences. A few successful combinations do not prove every seed solvable or collision-free.

## Roguelite persistent upgrades and run modifiers

Start from the run-room contract, then identify which visual state persists between runs and which resets. Build hub upgrade station and locked/available/completed states without changing shared interaction anchors. Represent run modifiers as detachable signs/material overlays or explicit room variants, not global destructive edits to the master. Check modifier combinations against existing elite/secret vocabulary so state cues do not conflict.

Render baseline, one persistent upgrade and a high-overlap modifier state from arrival and interaction views. If completed upgrades shift the player hand/door anchor, repair the art variant. If a modifier erases region identity, reduce its area/contrast or use a distinct signifier. Deliver persistence/reset state map and asset variants; save logic, progression economy and procedural fairness are explicitly unimplemented.
