# Blender Add-on and Extension Development

Preserve the user's existing project, approved contract and editable source. Read shared [asset requirements](../blender-development/references/asset-contract.md), [execution and ownership](../blender-development/references/execution-and-ownership.md) and [quality loop](../blender-development/references/quality-loop.md). These foundation references are resource dependencies, not an instruction to run another complete workflow.

- [Lifecycle And Context](references/lifecycle-and-context.md): read before implementation and evaluation.
- [Official Sources](references/official-sources.md): read for this branch or evidence gate.

Discover installed versions, capabilities and current scene before operating. Work in a disposable fixture or authorized object/output scope, keep recoverable originals and verify each changed behavior with evidence appropriate to that behavior. A read-only review returns findings; it does not run writer actions or persist reports. Packaging, export, process status, image review and target execution establish different results.

Conditional companions: `blender-pipeline-automation`, `blender-asset-validation`. Activate only the installed discipline needed by the requested work. Their names do not authorize installing tools, switching project configuration or publishing assets. If indispensable tools are absent, identify the gap and deliver feasible prepared work with unexecuted checks explicitly marked.

Use [the evaluation definitions](evals/evals.json) as realistic test inputs; their presence is not a passed test. Deliver current source and requested products, relevant versions/settings, exact files and actual check outcomes. Never infer visual approval or target behavior from a successful process or file write.
