# Card, Party and Idle Presentation: production playbook

## Brief, scale and evidence

Choose card/deck table, party stage, incremental scene, education model or rhythm lane. Collect camera crop, interface exclusion masks, participant count and minimum display size. The deliverable is an asset/stage, not an invented UI or scoring system.

## Asset kit and construction

Base stage, focal props, quiet background zones, state variants, camera-mask overlays and optional presentation animation. Cards need face/back/edge proxies; education needs separable, accurately related parts.

Give tokens real thickness and card borders that survive oblique views. Isolate emission accents from shared surfaces. For loops preserve source channels and exact return pose; low mesh count alone is no runtime-cost proof.

## Bounded layout recipe

These dimensions are a starting study, not established game rules.

1. Overlay supplied interface masks on a 16:9 camera before modeling ornaments.
2. Cards: place aspect-correct hand/draw/discard proxies; party: assign participant zones with shape and color cues.
3. Idle: build quiet/completed station states; rhythm: align beat props to lanes; education: split the assembly reversibly.
4. Review final crop and reduced-size output; if a loop is requested inspect start/end and nearby frames and report duration.

## Diagnostic images and acceptance

Flat zone mask, oblique/face-on cards, maximum token overlap and reduced-size preview. Disable bloom for accent checks. Inspect seam-adjacent frames for any loop.

## Specific failures and repairs

Ornament covers controls: move stage objects rather than shrinking approved masks. Rare-card glow destroys outline: isolate and reduce glow. Loop jump: repair animated transforms/material keys and inspect neighboring frames. Ambiguous educational assembly: key part relationships.
