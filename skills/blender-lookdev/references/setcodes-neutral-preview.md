# Reproducible neutral character preview

Use a dedicated owned review scene/file containing only the declared optimized asset copies. Inspect the saved scene, materials and display before diagnosing dull colors. Do not brighten albedo to compensate for exposure, an unrelated Material Preview HDRI or a photographic highlight rolloff. Capture a temporary unlit sRGB diagnostic under Standard when needed, then restore original materials; that diagnostic is not the final PBR result.

Validate the explicit neutral HDRI path and installed view-transform enum before creating lights/worlds. Discover runtime resource directories or request a project HDRI; a macOS Resources path is invalid on many Windows/Linux distributions. A failure must leave no half-created light rig. Snapshot scene world/camera/display and any viewport settings, prepare owned data, then link only after validation. Avoid changing every screen or deleting existing lights. If existing review lights are not owned by this operation, use another scene.

One repeatable source-informed starting preset uses EEVEE, sRGB display, Khronos PBR Neutral if actually available, Look None, exposure 0 and gamma 1. Use a neutral HDRI at strength 0.65, packed into the preview blend, and a separate neutral gray camera-ray background. For measured asset height h let `s=h/2.5`; at 2.5 m start key/fill/rim 250/90/180 W, area sizes 3/4/3 m, positions relative to center/ground `(-3,-4,4)`, `(3,-2,3)`, `(1,3,4)` m. Scale offsets/area size by s and power by s². Reject empty/nonfinite/zero-height bounds instead of hiding them with an arbitrary minimum. These are calibration candidates, not a requirement to relight every asset until colors match a screenshot.

Match rendered viewport Scene World/Lights to the saved render only in the owned view. Keep fixed camera, resolution, exposure and filtering between before/after. Frame body plus face/hands/seams and a grazing angle; include second light direction for normal/roughness changes. Khronos PBR Neutral and AgX can respond differently but neither guarantees identical pixels across Meshy, Blender and an engine. Confirm renderer illumination/exposure/display before attributing a mismatch to one application's saturation.

Pack/relink the actual HDRI and save a portable preview blend; reopen it to verify dependencies and settings. Keep cameras/lights outside the requested character FBX/GLB manifest. If transform/HDRI support differs, record the actual supported choice and recalibrate deliberately instead of silently substituting. Deliver preset settings, asset height, images and source/output hashes; neutral lighting alone is no art approval.
