Shared workflows consolidate overlap; one source entry can support several local owners without creating required dependencies between their optional workflows. A row declares instructional support, not successful Blender execution.

The [frozen upstream inventory](../scripts/data/blender-upstream-inventory.json) retains all **443 inventoried source paths**, Git blob identities, byte sizes and pinned repository trees. The [machine-readable coverage](../scripts/data/blender-source-coverage.json) records every entry mapping, its concrete capabilities, supporting local instruction files, exact inspected source resources and known limitations. Source entrypoints, package references/scripts/template assets, shared references and repository context are distinguished. The majid/setcodes entries additionally record a corrected adaptation decision and concrete local support for every package resource. `.gitignore`, plugin metadata and the upstream ZIP packager have explicit repository-context dispositions; they are reviewed source context and are not installed or activated. Legacy JSON/validator filenames remain for compatibility. Upstream executables and setup hooks are not installed by this inventory.

## Evidence boundaries

- Source-review provenance records which pinned information was inspected. Offline validation checks identities and relationships against that frozen inventory; it does not repeat a remote download or prove that a future upstream branch is unchanged.
- Structural coverage checks reject missing entries/resources, wrong blobs, unsafe local paths, undeclared cross-Skill resources and incoherent installation plans. Counts, text length and headings cannot establish semantic completeness or production quality.
- Full workflow, current-revision visual acceptance and target-engine acceptance remain separately marked not_run in this coverage manifest. API probes, author-written evaluation cases and separate native fixtures are narrower evidence and do not silently promote those statuses.
- Actual asset delivery still requires the relevant technical measurements, inspected final-revision images and target-engine checks. Read-only reviewers return findings; an authorized writer creates renders, corrections and persisted reports.

## Reading and maintaining the mapping

Choose the local package that matches the requested work. Its entrypoint routes to detailed production, variant or shared references. The matrix gives a concise capability summary and principal correction notes with a mechanics reference; the JSON retains the full declarations, correction notes and current supporting resource set, including shared foundation files and additional task references. Consult those resources for exact procedures, parameter choices, recipes, failure diagnosis and recheck criteria.

To change a pinned source, update its inventory records and the frozen snapshot identity/digest anchors in the validator from verified commit/tree/blob evidence, review the affected source entry and all supporting resources, and revise the declared capability/correction mapping. Preserve per-package license notices and existing primary provenance. To add or consolidate local packages, update the catalog, required resource edges, purpose bundle and both sides of the mapping. Never fill a missing coverage row with a runtime-success claim.

Validation commands:

~~~bash
node scripts/validate-blender-coverage.js
node tests/blender-coverage.test.js
~~~

The validator checks 110 direct purpose-bundle Skills and four Agents: Blender artist/reviewer, game designer and Godot developer. Required installation closures remain narrow: foundation 1 package, an ordinary specialist 2, common export 3 and an engine exporter 4. The game-design and Godot packages each have a standalone one-package required closure. Conditional/related routes describe task selection and do not install or execute the entire suite.

## Coverage is not acceptance

A maintained mapping can show where an instruction comes from and where its local adaptation is supported. A human or independent model must still assess whether those instructions actually preserve the relevant information and guide correct decisions. The validator deliberately has no minimum word-count, heading-count, image-similarity or blanket runtime-pass rule.
